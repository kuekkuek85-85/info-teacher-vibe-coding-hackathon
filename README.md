# 해커톤 베이스캠프

2026 바이브 코딩 역량강화 워크숍(8/16~17)에서 m1~m8 파이프라인 미션의 진행과 제출, 검토를 관리하는 LMS입니다.

기획은 클로드, 구현은 클로드 코드, 검토는 코덱스가 맡았습니다. 무엇을 받아들이고 무엇을 올릴지는 사람이 정했고, 커밋과 푸시 실행은 지시를 받은 클로드 코드가 했습니다. 그 기록은 `/making`에 공개되어 있습니다.

## 준비

### 1. Firebase 프로젝트

Firebase 콘솔에서 프로젝트를 만들고 다음 두 가지를 켭니다.

- Firestore Database (프로덕션 모드)
- Authentication > 로그인 방법 > 익명

### 2. 환경 변수

`.env.example`을 `.env.local`로 복사하고 값을 채웁니다.

```bash
cp .env.example .env.local
```

`FIREBASE_ADMIN_PRIVATE_KEY`는 서비스 계정 JSON의 private_key를 한 줄로 넣습니다. 줄바꿈은 `\n` 문자 그대로 둡니다.

`TEACHER_PIN`은 운영자 대시보드 비밀번호입니다. 워크숍마다 새로 정합니다.

### 3. 명단과 입장 코드 시딩

`scripts/seed.mjs`의 `roster` 배열을 실제 명단으로 바꿉니다. 동명이인이 있으면 이름을 "이름(소속)" 형식으로 적습니다.

```bash
npm run seed
```

참가자 22명에 예비 검토자 계정 하나를 더해 23명, 미션 8종이 들어갑니다.

입장 코드는 참가자 전원이 같은 것을 씁니다. `.env`의 `WORKSHOP_CODE`에 적어 두고, 당일 칠판에 적거나 `/teacher`의 수업 코드를 화면에 띄워 알려 주세요.

시딩은 여러 번 돌려도 안전합니다. 이미 열린 미션의 open 상태는 유지됩니다.

### 4. 보안 규칙 배포

```bash
npm run deploy:rules
```

`firestore.rules`를 Rules API 로 바로 올립니다. 콘솔의 Firestore > 규칙에 붙여넣어도 됩니다. 이 단계를 건너뛰면 누구나 남의 제출물을 고칠 수 있습니다.

규칙을 고칠 때마다 다시 돌리세요.

### 5. 로컬 실행

```bash
npm install
npm run dev
```

## 배포

Vercel에 저장소를 연결하고 `.env.local`의 값 12개를 전부 환경 변수로 등록합니다. `NEXT_PUBLIC_`으로 시작하는 값도 빠짐없이 넣습니다. 하나라도 빠지면 입장이 되지 않습니다.

| 변수 | 어디서 오는 값인가 |
|---|---|
| `NEXT_PUBLIC_FIREBASE_API_KEY` | Firebase 웹 앱 설정 |
| `NEXT_PUBLIC_FIREBASE_AUTH_DOMAIN` | Firebase 웹 앱 설정 |
| `NEXT_PUBLIC_FIREBASE_PROJECT_ID` | Firebase 웹 앱 설정 |
| `NEXT_PUBLIC_FIREBASE_STORAGE_BUCKET` | Firebase 웹 앱 설정 |
| `NEXT_PUBLIC_FIREBASE_MESSAGING_SENDER_ID` | Firebase 웹 앱 설정 |
| `NEXT_PUBLIC_FIREBASE_APP_ID` | Firebase 웹 앱 설정 |
| `FIREBASE_ADMIN_PROJECT_ID` | 서비스 계정 JSON 의 `project_id` |
| `FIREBASE_ADMIN_CLIENT_EMAIL` | 서비스 계정 JSON 의 `client_email` |
| `FIREBASE_ADMIN_PRIVATE_KEY` | 서비스 계정 JSON 의 `private_key` |
| `TEACHER_PIN` | 직접 정하는 값 |
| `WORKSHOP_CODE` | 참가자 전원이 함께 쓰는 수업 코드 |
| `FALLBACK_REVIEWER_NAME` | 예비 검토자 계정 이름 (기본 홍길동) |

`FALLBACK_REVIEWER_NAME` 을 빠뜨리면 학생이 홀수일 때 셔플 배정이 오류로 멈춥니다. 엉뚱한 강사가 조용히 배정되는 것보다 낫다고 보고 그렇게 만들었습니다.

환경은 Production, Preview, Development 셋 다 체크합니다.

### 빌드가 실패할 때

`No Output Directory named "public" found` 오류가 나면 Vercel 이 이 프로젝트를 Next.js 로 알아보지 못한 것입니다. 프로젝트의 Settings > General > Framework Preset 을 Next.js 로 바꾸고 다시 배포하세요. 저장소의 `vercel.json` 이 프레임워크를 지정하고 있으니, 그 파일이 포함된 커밋으로 배포해도 해결됩니다.

Root Directory 도 함께 확인하세요. 저장소 루트에 `package.json` 이 있으므로 비워 두거나 `./` 여야 합니다.

### 등록하는 두 가지 방법

대시보드에서 넣으려면 프로젝트의 Settings > Environment Variables 로 갑니다. 상단의 Import .env 버튼에 `.env.local` 파일을 올리면 한 번에 들어갑니다. 하나씩 붙여넣어도 됩니다.

CLI 로 넣으려면 이렇게 합니다.

```bash
npx vercel link
npx vercel env add FIREBASE_ADMIN_PRIVATE_KEY production
```

### private_key 주의

`FIREBASE_ADMIN_PRIVATE_KEY` 는 `\n` 이 들어간 긴 한 줄입니다. `.env.local` 에 적힌 값을 그대로 붙여넣으면 됩니다. 감싼 큰따옴표가 딸려 들어가도 코드가 벗겨 내고, `\n` 도 줄바꿈으로 되돌립니다. 두 경우 모두 인증되는 것을 확인했습니다.

줄바꿈을 실제 개행으로 풀어서 여러 줄로 넣는 방식만 피하세요. 그건 처리하지 않습니다.

값이 잘못됐는지는 배포 후 입장을 시도하면 압니다. 입장이 계속 거부되면서 Vercel 함수 로그에 `Failed to parse private key` 가 보이면 이 값이 원인입니다.

### 배포 직후 리허설

Firebase 없이는 저장과 인증 경로를 검증할 수 없습니다. 배포한 뒤 실제 계정으로 아래를 한 번씩 밟고 워크숍을 시작하세요. 30분이면 끝납니다.

입장

- [ ] 명단에 있는 이름과 코드로 입장된다
- [ ] 틀린 코드, 명단에 없는 이름은 거부된다
- [ ] 다른 기기에서 같은 이름으로 들어가면 이미 쓰는 중이라며 막힌다
- [ ] `/teacher`에서 그 이름의 이름 풀기를 누르면 새 기기로 들어가지고, 작성 내용이 그대로 보인다
- [ ] 앞 기기에서 글을 쓰면 입장 만료 안내가 뜨고, 재입장하면 이어서 쓸 수 있다

저장

- [ ] 글을 쓰고 1.5초 뒤 저장 표시가 뜬다
- [ ] 개발자 도구로 네트워크를 끊고 쓰면 오류 안내가 뜨고, 연결을 되살리면 저절로 저장된다
- [ ] 빠르게 입력한 직후 제출을 눌러도 마지막 글자까지 저장된다
- [ ] m6에 들어가 아무것도 고치지 않고 제출해도 지시문이 저장된다

운영

- [ ] `/teacher`에서 미션을 열면 다른 브라우저의 참가자 화면에서 자물쇠가 1초 안에 풀린다
- [ ] 틀린 PIN으로는 들어가지 못한다
- [ ] 셔플 배정 후 학생 전원에게 검토 상대가 붙고, 홀수면 강사에게도 붙는다
- [ ] 아직 입장하지 않은 사람도 배정에서 빠지지 않는다
- [ ] 배정된 상대에게 검토를 저장하면 상대 화면의 받은 검토에 나타난다
- [ ] 막혔어요를 누르면 운영자 큐에 뜨고, 해제하면 사라진다

규칙

- [ ] 남의 progress 문서를 개발자 도구로 고치면 거부된다
- [ ] 배정되지 않은 상대에게 검토를 쓰면 거부된다

리허설로 쌓인 데이터를 지우고 미션을 다시 닫으려면 이렇게 합니다. 명단과 입장 코드, 미션 내용은 남습니다.

```bash
npm run reset
```

한 번 연 미션은 닫지 않습니다. 참가자가 이전 단계로 돌아가 고치는 것이 설계 의도입니다. 닫기 버튼은 사고가 났을 때만 씁니다.

### 예비 검토자

학생이 홀수면 짝이 없는 한 명이 남습니다. 그 사람의 검토자로 `FALLBACK_REVIEWER_NAME`에 적힌 계정이 배정됩니다. 기본값은 홍길동입니다.

이 계정은 role 이 staff 라서 짝짓기 대상에 들어가지 않고, 광장의 진행률 집계에서도 빠집니다. 강사 중 한 사람이 이름과 입장 코드로 들어와 m5 화면에서 검토를 씁니다. 학생 화면이 어떻게 보이는지 미리 확인하는 용도로도 씁니다.

학생이 짝수면 이 계정은 배정에 나서지 않습니다. 이름을 바꾸려면 `scripts/seed.mjs`의 `extraAccounts`와 `.env` 의 `FALLBACK_REVIEWER_NAME`을 함께 고치세요.

## 개인정보

수집하는 정보는 이름과 소속뿐입니다. 미션 폼 상단에 학생 실명을 적지 말라는 안내가 붙어 있고, 스크롤을 내려도 따라옵니다. 글을 쓰는 동안 계속 보이는 자리입니다.

한계를 네 가지 밝혀 둡니다. 서로 아는 22명이 이틀 동안 쓰는 도구라 이 수준에서 멈췄습니다.

첫째, 수업 코드가 하나라서 코드를 아는 사람은 명단의 어느 이름으로든 들어올 수 있습니다. 다만 이미 다른 기기가 쓰고 있는 이름은 막히고, 운영자가 `/teacher`에서 이름 풀기를 눌러야 넘어갑니다. 기기를 바꾸거나 브라우저를 지운 참가자가 있으면 이 버튼을 눌러 주세요.

둘째, 익명 인증만 거치면 다른 참가자의 제출물을 읽을 수 있습니다. 미션의 공개 범위 설정은 화면에 무엇을 보여 줄지 정하는 것이지 접근을 막는 장치가 아닙니다. `/plaza`는 입장 코드 없이도 열리므로 배포 URL을 아는 사람은 진행 현황을 볼 수 있습니다. 워크숍이 끝나면 배포를 내리거나 데이터를 지우세요.

셋째, 잠긴 미션에 쓰는 것은 화면에서만 막습니다. 보안 규칙은 progress 문서 안의 어느 미션이 바뀌었는지 특정하지 못합니다.

넷째, 수업 코드와 운영자 PIN에는 시도 횟수 제한이 없습니다. 실패 응답을 1초 늦추는 선에서 멈췄습니다.

### 종료 후 데이터 삭제

워크숍이 끝나고 일주일 안에 지웁니다.

1. Firestore에서 `progress`, `reviews`, `codes`, `roster` 컬렉션 삭제
2. Authentication에서 익명 사용자 전체 삭제
3. Vercel 환경 변수의 `WORKSHOP_CODE` 를 지우거나 배포를 내림
4. 참가자 산출물을 연구회와 공유할 때는 이름을 빼고 내용만 옮깁니다

`missions`와 `config`는 콘텐츠라 남겨 두어도 됩니다.
