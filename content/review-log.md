## 1차 검토 — 구현 계획 (2026-08-15)

코덱스에게 PRD와 구현 계획을 주고 검토를 시켰습니다. 지적은 열두 갈래로 나왔고, 대부분 받아들였습니다.

### 받아들인 것

| 지적 | 어떻게 고쳤나 |
|---|---|
| 이름만으로 입장하면 미접속자 이름을 선점할 수 있다 | 입장 코드 6자리를 도입하고, 코드 검증과 소유권 연결을 서버 라우트로 옮김 |
| 기기 초기화가 ownerUid를 지우면 그 사람은 영구 차단된다 | 초기화 버튼 자체를 없앰. 코드가 본인 증명이라 재입장하면 소유권이 자동으로 옮겨감 |
| 임시 저장 키가 하나라 미션끼리 덮어쓴다 | 미션별 키로 분리하고, 연결이 돌아오면 자동 재저장 |
| 디바운스가 남은 채 제출하면 마지막 입력이 빠진다 | 제출 전에 대기 중인 저장을 먼저 밀어 넣고, 실패하면 제출을 멈춤 |
| 보안 규칙이 Firestore에 없는 split() 함수를 쓴다 | 문자열 결합 비교로 바꾸고, 배정된 상대인지까지 검증 |
| 서버가 클라이언트가 보낸 uid를 그대로 믿는다 | ID 토큰을 검증해 uid를 서버에서 꺼냄 |
| 미입장자가 있으면 셔플 배정이 누락된다 | 배정 시 골격 문서를 만들어 전원 배정 |
| 동료에게 받은 코멘트를 볼 방법이 없다 | m5 화면에 받은 검토 섹션 추가 |
| m6 지시문 템플릿 프리필이 빠졌다 | m4의 테스트 설계를 끼워 넣어 첫 지시문에 자동 입력 |
| 막혔어요 버튼을 어느 화면에 붙일지 계획에 없다 | 홈과 미션 폼 두 곳으로 명시 |
| 검토 기록을 남기는 절차가 계획에 없다 | 지금 읽고 계신 이 문서가 그 절차입니다 |
| 배포 후 점검 절차가 없다 | 배포 직후 확인할 항목을 README 체크리스트로 |

### 거부하거나 미룬 것

| 지적 | 왜 |
|---|---|
| 광장과 이 페이지를 최소판으로 줄여라 | 광장은 서로의 진행을 보는 장치라 줄이면 수업 설계가 무너집니다. 시간이 부족하면 그때 줄입니다 |
| 관리자 PIN에 시도 제한을 붙여라 | 하루 쓰는 도구에 로그인 인프라를 얹기보다, 실패 응답을 1초 늦추는 선에서 멈췄습니다 |
| 인증만 하면 남의 제출물을 읽을 수 있다 | 사실입니다. 22명이 서로 아는 자리이고 이틀 뒤 데이터를 지웁니다. 숨기는 대신 README에 적어 두는 쪽을 골랐습니다 |

## 2차 검토 — 구현 코드 (2026-08-15)

구현을 마친 뒤 저장소 전체를 다시 코덱스에게 보냈습니다. 이번에는 실제로 돌아가는 코드를 두고 하는 검토라 지적이 더 구체적으로 나왔습니다.

### 받아들인 것

| 지적 | 어떻게 고쳤나 |
|---|---|
| 시딩을 다시 돌리면 입장 코드가 바뀌어 인쇄물이 무효가 된다 | 이미 발급한 코드는 그대로 두고, 명단에서 빠진 사람 문서만 지우도록 |
| 시딩이 발표 순서를 초기화한다 | config 문서가 없을 때만 만들도록 |
| 소유권이 넘어간 기기에서 저장 거부가 나도 안내가 없다 | 권한 거부를 붙잡아 입장 만료 안내를 띄우고 재입장으로 보냄 |
| m6 프리필을 고치지 않고 제출하면 빈 값으로 저장된다 | 프리필한 순간 저장을 예약하도록 |
| 동료 검토 저장에 실패 처리와 중복 클릭 방지가 없다 | 저장 중 잠금과 실패 안내 추가 |
| 광장이 공개 미션의 모든 필드를 내보낸다 | 내보낼 필드를 두 개로 못박음. 미션에 필드가 늘어도 저절로 공개되지 않음 |
| 막혔어요 큐가 이름순이라 오래 기다린 사람이 묻힌다 | 손 든 시각 순으로 |
| 저장된 PIN 만 있으면 재검증 없이 대시보드가 열린다 | 새로고침할 때마다 서버에 다시 확인 |
| reviews 규칙이 체크리스트 키와 길이를 제한하지 않는다 | 허용 키와 코멘트 길이를 규칙에 명시 |
| progress 규칙이 문서 구조를 검증하지 않는다 | missions·currentStep·stuck 자료형과 개수 제한 추가 |
| 미션 폼에 실명 금지 안내가 없다 | 입력 화면 하단에 고정 |
| Firebase 없이 검증하지 못한 항목이 많다 | 배포 직후 리허설 체크리스트 18항목을 README에 |

### 거부하거나 미룬 것

| 지적 | 왜 |
|---|---|
| 잠긴 미션 제출을 규칙으로 막아라 | 막고 싶었지만 Firestore 규칙은 progress 문서 안의 어느 미션이 바뀌었는지 특정하지 못합니다. 화면에서만 막고 한계를 README에 적었습니다 |
| 입장 코드와 PIN 에 시도 제한을 붙여라 | 1차 검토 때와 같은 판단입니다. 하루 쓰는 도구에 인프라를 더 얹지 않았습니다 |
| /plaza 를 입장한 사람에게만 열어라 | 광장을 보조 모니터에 상시 띄우려면 로그인 없이 열려야 편합니다. 대신 워크숍이 끝나면 배포를 내리라고 README에 적었습니다 |

### 검토와 별개로 직접 잡은 것

셔플 배정 로직을 따로 시험하다가 학생이 한 명뿐일 때 자기 자신을 검토 상대로 배정하는 버그를 찾았습니다. 코덱스도 놓친 자리였고, 검증 스크립트가 아니었으면 그냥 지나갔을 겁니다.

## 3차 검토 — 푸시 직전 (2026-08-16)

배포를 앞두고 한 번 더 검토를 받았습니다. 이번에는 코덱스가 두 차례 푸시를 막았습니다.

### 첫 번째 제동

화면에서 실명 금지 안내를 빼 달라는 요청을 받고 입장 화면과 홈에서 지웠는데, 미션 폼 맨 아래 남긴 문단은 스크롤을 내리면 보이지 않아 PRD가 요구한 고정 노출이 아니라는 지적이 나왔습니다. 맞는 말이라 제목 위 sticky 배너로 옮겼습니다. 이제 글을 쓰는 내내 화면에 붙어 있습니다.

예비 검토자를 홍길동으로 바꾸면서 설정이 틀리면 조용히 다른 강사가 배정되던 것도 지적됐습니다. 이름이 없거나 명단에 없거나 역할이 학생이면 배정을 중단하고 이유를 말하도록 고쳤습니다.

재시딩할 때 명단에서 빠진 사람의 제출 기록이 남아 광장에 유령처럼 뜬다는 점, 리셋해도 발표 순서가 남는다는 점도 함께 고쳤습니다.

### 두 번째 제동

고친 뒤 다시 검토를 받았더니 세 가지가 더 나왔습니다. 이전 환경 변수가 남아 있으면 새 설정을 건너뛰고 옛 강사가 배정되는 경로가 살아 있었습니다.

가장 뼈아픈 지적은 제 검증 스크립트를 향한 것이었습니다. 실제로 쓰이는 함수가 아니라 같은 판단을 흉내 낸 복사본을 시험하고 있었습니다. 통과했다는 결과가 아무것도 보장하지 않았던 셈입니다. 판단식을 파일 하나로 분리해 앱과 검증이 같은 코드를 쓰도록 바꿨습니다.

운영자 화면이 모든 오류를 "PIN을 확인하세요"로 뭉뚱그려서, 설정이 잘못됐을 때 원인을 알 수 없다는 지적도 받아들였습니다.

### 세 번째에 통과

세 번째 검토에서 차단 사유가 없다는 답이 나왔고, 그때 푸시했습니다.

남길 말은 이겁니다. 검토를 세 번 받는 동안 제가 "다 고쳤다"고 생각한 시점이 두 번 있었습니다. 두 번 다 틀렸습니다. 특히 검증 스크립트가 가짜를 시험하고 있었다는 것은, 통과 표시를 믿는 일이 얼마나 위험한지 보여 줍니다. 초록불이 켜졌다고 검증된 것은 아닙니다. 무엇을 시험하고 있는지 확인해야 검증입니다.

## 4차 검토 — 입장 코드 화면 (2026-08-16)

강사 대시보드에 참가자 입장 코드를 띄워 달라는 요청을 받았습니다. 코드는 Firestore 보안 규칙이 클라이언트 읽기를 막고 있어서, PIN을 확인한 서버 경로로만 내려오게 만들었습니다.

여기서도 두 번 막혔습니다.

첫 번째로 코드를 기본으로 펼쳐 둔 것이 지적됐습니다. 강사가 화면을 프로젝터로 넘기는 순간 전원의 코드가 한꺼번에 노출됩니다. 기본을 가림으로 바꾸고, 경고 문구도 카드 목록 아래가 아니라 버튼 위로 올렸습니다. 조회에 실패했을 때 "불러오는 중"이 영원히 남는 문제와, 잠근 뒤에도 이전 코드가 메모리에 남는 문제도 함께 고쳤습니다.

두 번째 지적이 날카로웠습니다. 조회가 도는 도중에 잠그면, 뒤늦게 도착한 응답이 이미 지운 코드를 되살립니다. 화면은 잠겨 있는데 데이터는 살아 있는 상태입니다. 요청마다 세대 번호를 붙여 잠금 이후에 온 응답은 버리도록 고쳤습니다. 응답을 3초 늦춘 뒤 그사이에 잠그는 방식으로 재현해서 확인했습니다.

이번에 배운 것은 이겁니다. 화면에서 사라진 것과 실제로 없어진 것은 다릅니다. 눈으로 확인하는 검증은 여기까지 닿지 못합니다.
