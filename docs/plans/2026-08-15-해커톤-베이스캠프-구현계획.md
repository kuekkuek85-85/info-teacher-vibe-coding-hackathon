# 해커톤 베이스캠프 구현 계획 (v4 — 코덱스 검토 반영, 공용 수업 코드)

> **v4 변경(2026-08-16):** 개인별 입장 코드를 없애고 워크숍 전체가 하나의 수업 코드를 쓴다. 코드는 `WORKSHOP_CODE` 환경 변수에만 있고 `codes` 컬렉션은 쓰지 않는다. 코드가 공용이라 이름 선점이 가능해지므로, `/api/enter` 가 트랜잭션으로 `ownerUid` 를 확인해 이미 다른 기기가 쓰는 이름은 409 로 막고, 운영자가 `/teacher` 의 이름 풀기(`releaseName`)를 눌러야 넘어간다. 아래 본문의 개인별 코드 서술은 v3 기준이다.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 8/16~17 워크숍(22명)에서 m1~m8 파이프라인 미션의 진행·제출·검토를 실시간으로 관리하는 LMS를 오늘 밤 안에 P0 완성한다.

**Architecture:** Next.js App Router 클라이언트 중심 구조. Firestore를 유일한 저장소로 쓰고 onSnapshot으로 실시간 반영한다. 참가자는 이름 + 입장 코드로 입장하며, 코드 검증과 익명 인증 uid의 소유권 연결은 서버 라우트(`/api/enter`)가 admin SDK로 처리한다. 운영자 기능은 PIN 검증 서버 라우트(`/api/admin`) 경유. 미션은 `missions` 컬렉션 데이터로만 렌더링해 콘텐츠 교체만으로 새 미션이 동작한다.

**Tech Stack:** Next.js(App Router) + React + Tailwind CSS + Firebase(Firestore, Anonymous Auth) + firebase-admin + Vercel 배포. 폰트 Pretendard Variable.

## Global Constraints

- 제작 파이프라인: 구현 클로드 코드, 검토 코덱스, 최종 결정·커밋·푸시는 사람. **AI는 git commit/push를 실행하지 않는다.**
- 오늘 밤 제작에는 TDD를 적용하지 않는다. 각 태스크는 브라우저 확인으로 검증한다.
- 다크 온리. canvas `#090909`, surface-1 `#141414`, surface-2 `#1c1c1c`, ink `#ffffff`, ink-muted `#999999`. 텍스트 회색은 이 둘뿐.
- `#0099ff`는 링크·포커스 링(`rgba(0,153,255,0.15) 0 0 0 1px`)·선택 표시에만. 배경·버튼 채움 금지.
- 그라디언트는 카드 단위로만, 화면당 1~2개: 현재 스텝 violet `#6a4cf5`, 검토 게이트(m5·m8) magenta `#d44df0`, 막혔어요 coral `#ff5577`.
- CTA는 흰 필 버튼(흰 배경+검정 텍스트, rounded 100px). 보조는 차콜 필(surface-1). 고스트·보더 버튼 금지.
- 폰트는 전부 Pretendard Variable. 디스플레이 자간 -0.03em, 본문 -0.01em. 굵기 500~700. 숫자 통계 구간 `tnum`.
- UI 문구는 COPY.md 준수: 본문 볼드 금지, 이모지는 막혔어요 버튼(🙋)만, 대시 부가설명 금지, 번역투 금지, 단언형, 같은 어미 3연속 금지. 프롬프트 카드 원문은 원고 §B 그대로 시딩.
- 한 번 열린 미션은 닫지 않는다(닫기는 비상용). 열린 미션은 항상 재수정 가능.
- 폼 자동 저장 1.5초 디바운스. 저장 실패 시 원인 1문장 + 다음 행동 1문장 안내와 로컬 임시 보관(미션별 키).
- 동시 접속 22명, 실시간 반영 1초 이내(onSnapshot).
- 수집 정보는 이름·소속만. 제출물에 학생 실명 입력 금지 안내 고정 노출.
- 환경 변수: `NEXT_PUBLIC_FIREBASE_*`, `FIREBASE_ADMIN_*`, `TEACHER_PIN`, `WORKSHOP_CODE`(참가자 전원이 함께 쓰는 수업 코드), `FALLBACK_REVIEWER_NAME`(학생이 홀수일 때 짝 없는 한 명을 검토할 계정).
- 데이터 접근의 정직한 한계: Firestore 규칙상 인증된 참가자는 모든 progress·reviews를 읽을 수 있다. visibility는 화면 노출 필터이며 접근 제어가 아니다. 신뢰 집단 22명, 이틀 행사, 종료 후 삭제를 전제로 수용하고 README에 명시한다.

## 1. 사용자 시나리오

### 1.1 수강생 김교사 (2일차 오전, 정상 흐름)

1. 어제 접속했던 배포 URL을 다시 연다. localStorage에 이름이 남아 있어 입장 화면 없이 바로 홈이 뜬다.
2. 홈 상단 스텝퍼에서 m1·m2에 체크가 붙어 있고, 오늘 아침 열린 m3 칸이 violet으로 빛난다. m6~m8은 자물쇠다.
3. m3 카드를 눌러 미션 폼으로 들어간다. 폼 상단에 어젯밤 숙제로 낸 m2의 "아이디어 한 줄"이 자동으로 표시된다.
4. 클로드와 대화한 결과를 폼에 옮겨 적는다. 입력을 멈추면 1.5초 뒤 "저장됨" 표시가 뜬다. 제출 버튼을 누르면 대기 중인 자동 저장이 즉시 반영된 뒤 제출되고, 스텝퍼의 현재 위치가 m4로 넘어간다.
5. m4에서 시나리오·와이어프레임·테스트 설계를 적고, m5(magenta 게이트)에서 검토 프롬프트 카드를 복사해 클로드 새 대화에 붙여넣은 뒤, 지적의 수용/거부를 기록한다. 배정된 동료의 m3·m4를 열람하고 체크리스트와 코멘트를 남긴다. 같은 화면에서 내가 받은 동료 검토 코멘트도 확인한다.
6. m6에 들어가면 첫 지시문 입력란에 지시문 템플릿이 미리 채워져 있다. 스택과 도구 이름만 바꿔 쓴다. 진행 중 계획 결함을 발견하고 스텝퍼에서 m4로 돌아가 수정한다.
7. 중간에 광장에서 동료들의 파이프라인 위치와 공개 제출물을 본다. m7 제출자의 배포 URL을 눌러 써 본다.
8. Firebase 설정에서 막히자 막혔어요 🙋 버튼을 누른다. 잠시 뒤 강사가 온다.

### 1.2 수강생 박교사 (실패·경계 흐름)

1. 이름 "박교사 "(뒤 공백)와 입장 코드를 입력한다. 공백이 정리되어 대조되고 정상 입장한다.
2. 명단에 없는 이름이나 틀린 코드를 입력하면 "이름 또는 입장 코드가 맞지 않습니다. 강사에게 확인해 주세요."가 뜨고 입장되지 않는다.
3. 잠긴 m6의 URL(`/mission/m6`)로 직접 접근하면 "아직 열리지 않은 미션입니다" 화면이 뜬다.
4. 작성 중 네트워크가 끊긴다. "저장하지 못했습니다. 연결이 돌아오면 자동으로 다시 저장됩니다." 안내가 뜨고 입력값은 미션별 로컬 키에 보관된다. 연결 복구(online 이벤트) 시 자동 재저장된다.
5. 태블릿으로 기기를 바꿔 이름 + 입장 코드로 다시 입장한다. 코드가 맞으므로 서버가 소유권을 새 기기로 옮기고, 작성하던 내용이 그대로 보인다.

### 1.3 운영자 이승엽

1. `/teacher`에 접속해 PIN을 입력한다. 틀리면 1초 뒤 "PIN이 맞지 않습니다. 다시 입력해 주세요."가 뜬다.
2. 22명 × 8미션 그리드가 실시간으로 갱신된다. 셀은 제출 완료·작성 중·미시작을 구분해 보여 준다.
3. 스프린트 1 시작 시각에 m3·m4·m5의 열기 토글을 누른다. 수강생 화면의 자물쇠가 1초 안에 풀린다. 닫기 버튼은 확인 대화상자 뒤에서만 동작한다.
4. 막혔어요 큐에 coral 하이라이트로 "김교사"가 뜬다. 가서 도운 뒤 큐에서 해제한다.
5. m5 시작 전 셔플 배정 버튼을 누른다. 학생들이 둘씩 상호 검토로 묶이고, 홀수라 남은 한 명은 이승엽이 검토자가 된다. 재실행 시 "이미 배정된 검토 상대가 바뀝니다" 확인 창이 뜬다.
6. 발표 전 m7 제출자를 순서 목록으로 지정하고 `/present`를 프로젝터에 띄운다(P1).

### 1.4 보조 강사 (role: staff)

1. 수강생과 동일하게 이름 + 입장 코드로 입장한다. 상단 바 이름 옆에 [강사] 배지가 붙는다.
2. 스텝퍼와 미션은 볼 수 있으나 제출 의무가 없고, 광장에서는 배지만 표시되고 미니 스텝퍼와 진행률 집계에서 제외된다.

## 3. 데이터 모델 (Firestore)

- [ ] **Step 1: 디바운스 저장 훅** — 로컬 보관 키는 `draft:{name}:{missionId}`. 저장 성공 시 저장 시점 스냅숏과 현재 pending이 같을 때만 pending·로컬 키를 지운다(저장 중 새 입력 유실 방지). `flush()`는 성공 여부를 반환해 제출이 실패를 감지하게 한다. `window "online"` 이벤트에서 자동 재시도.

```ts
export function useDebouncedSave(name: string, missionId: string,
  save: (data: Record<string, string>) => Promise<void>) {
  const [status, setStatus] = useState<"idle"|"saving"|"saved"|"error">("idle");
  const timer = useRef<ReturnType<typeof setTimeout>>();
  const pending = useRef<Record<string, string> | null>(null);
  const key = `draft:${name}:${missionId}`;
  const run = async (): Promise<boolean> => {
    const snapshot = pending.current;
    if (!snapshot) return true;                 // 저장할 것 없음 = 성공
    setStatus("saving");
    try {
      await save(snapshot);
      if (pending.current === snapshot) {       // 저장 중 새 입력이 없을 때만 정리
        pending.current = null;
        localStorage.removeItem(key);
      }
      setStatus("saved");
      return true;
    } catch { setStatus("error"); return false; }
  };
  const queue = (data: Record<string, string>) => {
    pending.current = data;
    localStorage.setItem(key, JSON.stringify(data));
    clearTimeout(timer.current);
    timer.current = setTimeout(run, 1500);
  };
  const flush = (): Promise<boolean> => { clearTimeout(timer.current); return run(); };
  useEffect(() => {
    const retry = () => { if (status === "error") run(); };
    window.addEventListener("online", retry);
    return () => window.removeEventListener("online", retry);
  }, [status]);
  return { status, queue, flush, draftKey: key };
}
```

```
rules_version = '2';
service cloud.firestore {
  match /databases/{db}/documents {
    match /roster/{name}   { allow read: if request.auth != null; allow write: if false; }
    match /missions/{id}   { allow read: if request.auth != null; allow write: if false; }
    match /config/{doc}    { allow read: if request.auth != null; allow write: if false; }
    match /codes/{name}    { allow read, write: if false; }   // /api/enter(admin) 전용
    match /progress/{name} {
      allow read: if request.auth != null;
      allow create: if false;                                  // 생성은 /api/enter만
      allow update: if request.auth != null
        && resource.data.ownerUid == request.auth.uid
        && request.resource.data.ownerUid == resource.data.ownerUid      // 소유권 변경 불가
        && request.resource.data.name == resource.data.name              // 신원 필드 변조 불가
        && request.resource.data.school == resource.data.school
        && request.resource.data.role == resource.data.role
        && (!('reviewTarget' in request.resource.data)                   // 배정 변경 불가
            || request.resource.data.reviewTarget == resource.data.get('reviewTarget', ''));
    }
    match /reviews/{id} {
      allow read: if request.auth != null;
      allow create, update: if request.auth != null
        && id == request.resource.data.reviewer + '_' + request.resource.data.target
        && get(/databases/$(db)/documents/progress/$(request.resource.data.reviewer)).data.ownerUid == request.auth.uid
        && request.resource.data.target
           == get(/databases/$(db)/documents/progress/$(request.resource.data.reviewer)).data.reviewTarget;
    }
  }
}
```
